# Черновик содержимого встроенной справки — на ревью

Этот файл — предварительное текстовое наполнение панели «Справка» (для вашего ревью, ДО начала
вёрстки самой панели). Каждый раздел справки — заголовок верхнего уровня (`#`). Внутри раздела —
предполагаемые подпункты (`##`/`###`) и краткое содержание, а не финальные формулировки текста.

Открытые вопросы к вам — в конце файла, перед тем как начну вёрстку панелей.

---

# Работа со схемой

Здесь описана базовая работа с узлами и диаграммой.  

## Узлы и типы
- Существуют три типа узла: **Узел** (обычный), **Тест** (к нему привязывается тест), **Ссылка** (для внешних
  URL — URL хранится как комментарий узла).
- Создание узла: кнопки группы «Узлы» на тулбаре (Текст/Тест/Ссылка) — добавляют дочерний узел к
  выделенному, либо к корню, если ничего не выделено.
- Для ссылки при создании запрашивается URL (диалог браузера) — сохраняется в комментарий; переход
  по ссылке — Ctrl+клик по тексту узла.
- Направления ветвей: у корня узлы растут в 4 стороны (вверх/вниз/влево/вправо), выбор направления —
  через всплывающую панель при наведении на корень.

## Редактирование
- Двойной клик по тексту узла — редактирование текста.
- Всплывающая панель при наведении на узел: добавление дочерних узлов, комментарий, удаление,
  сброс ручной позиции.
- Кнопка «Выполнен» (группа «Узлы») — отмечает/снимает отметку с выделенного узла (зелёная рамка).
- Кнопка «Удалить» (группа «Узлы») — удаляет выделенный узел; его дети переходят к его родителю
  (не удаляются каскадно).

## Перемещение и навигация
- Drag & drop узла — перенос к другому родителю (проверка циклов) или ручное позиционирование на
  свободном месте холста.
- Панорамирование: зажать левую кнопку мыши на пустом фоне и потянуть; либо обычная прокрутка.
- Комментарий узла (короткая подпись под узлом) — отличается от полноценной заметки (см. ниже).

## Заметки (Markdown)
- Кнопка «Панель» открывает боковую панель; для обычного узла показывается редактор заметки.
- Форматирование: полужирный/курсив/подчёркнутый/заголовок/списки/ссылка/изображение.
- Переключение между Markdown-исходником и визуальным редактором.

## Тесты
- Узел типа «Тест» — при открытой панели показывает: «теста ещё нет» / стартовый экран (с прошлым
  результатом, если есть) / экран вопроса / экран результата.
- Вопросы с одним (radio) или несколькими (чекбоксы) правильными ответами.
- Порог прохождения (%), результат сохраняется только по завершении/прерыванию попытки (история
  прошлых попыток не хранится).
- Тесты создаются НЕ в самом приложении — редактора вопросов в UI нет (см. ниже разделы про LLM).

## Хранение и обмен данными
- Автосохранение в localStorage браузера.
- Импорт/экспорт JSON (кнопки группы «Схема») — полный перенос диаграммы между сессиями/машинами.
- Кнопка «Очистить» — полный сброс схемы к одному узлу в центре (с подтверждением, необратимо).
- Переключение светлой/тёмной темы (кнопка «Тема»).

# Работа с LLM в режиме чата

Как передать диаграмму (или её часть) в обычный чат с LLM (ChatGPT/Claude/др.) и получить готовый
JSON-файл для импорта — без каких-либо специальных инструментов у модели, просто текстовый диалог.

## Когда это нужно
- Быстро сгенерировать черновик структуры диаграммы по теме.
- Попросить модель написать текст заметок или вопросы теста для конкретных узлов.
- Модель не обязана «знать» формат заранее — вы прикладываете описание формата вместе с запросом.

## Файл формата данных
- Ссылка на скачивание: **DATA_FORMAT.md** (описание JSON-формата диаграммы: структура узла,
  типы узлов, атрибуты `data.*`, схема теста, поддерживаемый Markdown, версионирование).
- Инструкция: приложить этот файл к сообщению модели (или вставить его содержимое текстом), а затем
  сформулировать запрос.

## Пример запроса пользователя к LLM (черновик формулировки)
> «Вот описание формата данных mind map-приложения (файл DATA_FORMAT.md). Сгенерируй диаграмму по
> теме "Основы фотосинтеза": корень + 4–6 подтем, у двух подтем добавь короткие заметки, у одной —
> тест на 3 вопроса. Верни готовый JSON целиком по этому формату.»

## Что делать с результатом
- Скопировать JSON-ответ модели в файл (например `mindmap.json`).
- Импортировать через кнопку «Импорт JSON» в тулбаре приложения.
- Возможные проблемы (модель что-то напутала в формате) и на что обратить внимание при проверке —
  сослаться на чек-лист из DATA_FORMAT.md.

# Работа с агентской LLM

Как использовать данные диаграммы с LLM-агентом, который умеет сам следовать инструкциям и
самостоятельно выполнять пошаговый алгоритм (в отличие от простого чат-запроса из предыдущего
раздела) — например, agent-режимы в IDE/чатах, кастомные GPT с файлами, или любые агентские
платформы, поддерживающие подключение «навыков»/инструкций.

## Отличие от режима «просто чат»
- Обычный чат (предыдущий раздел) — одноразовый запрос-ответ с приложенным описанием формата.
- Агентский режим — модели передаётся файл-инструкция (навык), который она использует
  систематически: соблюдает чек-листы, ветвления «если/иначе», формат ответа, ограничения — то
  есть годится для более сложных/многошаговых правок существующей схемы.

## Файл навыка
- Ссылка на скачивание: **SKILL.md** (пошаговая инструкция для агента: как читать/создавать/менять
  диаграмму, типовые операции — добавление/удаление/перемещение узла, работа с заметками и тестами,
  чек-лист валидации перед выдачей результата).
- Инструкция: подключить/приложить этот файл агенту как системную инструкцию или файл контекста
  (конкретный способ подключения зависит от платформы агента — упомянуть 1–2 распространённых
  варианта, например «загрузить как файл проекта» / «вставить в системный промпt»).

## Пример сценария использования (черновик)
> Пользователь прикладывает SKILL.md и текущий экспортированный JSON диаграммы, просит агента:
> «Добавь к узлу "Введение" тест на 5 вопросов по теме и заметку с кратким планом раздела».
> Агент читает файл, следует чек-листу, возвращает полный обновлённый JSON.

## Ограничения
- Агент работает только с тем, что ему передали текстом (у него нет доступа к файловой системе
  приложения) — результат нужно вручную импортировать обратно через «Импорт JSON».
- Агент не может создавать новые типы узлов — типы зафиксированы в приложении.
